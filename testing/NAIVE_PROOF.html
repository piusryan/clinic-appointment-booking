Why only 2 requests "saw a free slot" but 48 wrote? Node.js is single-threaded. Each request hits await findOne() and yields the event loop. By the time most callbacks fire the first write hasn't committed yet — so they all see an empty slot, pass the check, and all 48 writes land. The check and the write are separated by an I/O boundary; no amount of care in JavaScript closes that gap.
Phase Comparison — Same Code, One Variable

Phase A — No Index

Naive check-then-write. The availability check and the insert are separated by an await. All 50 requests see the slot as free during the check window.

48 rows

48 double-bookings for one slot. A real clinic nightmare.

Phase B — Partial Unique Index

Identical application code. The only difference: the partial unique index on (doctor, startsAt) where status='booked'. MongoDB's storage engine rejects duplicates atomically.

1 row

Exactly one booking survives. 49 get E11000 → mapped to HTTP 409.
